# Trinity – Flight Computer Firmware

Firmware for **Trinity**, a self-built model rocket with three solid motors, each mounted on a two-axis gimbal (thrust vector control, TVC). The flight computer is a custom PCB based on an **STM32F405RG**, programmed bare-metal in C with STM32CubeIDE / HAL.

Project video: https://youtu.be/A9ZqcneifH0

## What the firmware does

- **Sensors** – IMU (accelerometer + gyroscope) and barometer on SPI with DMA, motor ignition sensing through the ADC.
- **Attitude** – gyro bias calibration on the pad, quaternion propagation of the body attitude and of a time-varying target attitude.
- **Control** – PID on the attitude error (with anti-windup), converted into a required torque through Euler's rotational equations.
- **Control allocation** – the required torque is mapped analytically to the six gimbal angles of the three motors, with servo limits. Motors that are not burning are excluded from the allocation, so the remaining ones take over the control (engine-out tolerance).
- **Recovery** – apogee detection and parachute deployment.
- **Logging** – high-rate logging to NOR flash, then transfer to SD card (FatFs).
- **Ground modes** – an umbilical connector selects the mode (`LAUNCH`, `LOG`, `TEST`). `TEST` replays logged flight data through the same code for post-flight analysis.

## Where to look

| File | Content |
|---|---|
| `Core/Src/main.c` | Initialisation, mode selection and main control loop |
| `Core/Src/trinityfunctions.c` | Sensor drivers, flash/SD logging, quaternion math, controller and control allocation |
| `Core/Inc/trinityfunctions.h` | Function overview |

Everything outside `Core/` (HAL drivers, FatFs, startup files) is generated by STM32CubeMX or comes from third-party libraries.
